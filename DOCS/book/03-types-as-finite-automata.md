# Chapter 3 — Schemas as Finite Automata

## **3.1 Motivation**

A schema in `k` describes a set of finite labeled trees, which can be recognized by a finite tree automaton (FTA). Equivalently, a schema definition can be seen as a context-free grammar (CFG), where the payloads of the schema are the derivation trees of the grammar.

For example, the recursive schema of a `list`:

```k-lang
bool = ?< {} true, {} false >;
list = ?< {} nil, { < {} true, {} false > head, L tail } cons > = L;
```

corresponds to the following 4-rule grammar:

```bnf
1: <bool> ::= {} |true
2: <bool> ::= {} |false
3: <list> ::= {} |nil
4: <list> ::= { <bool> head, <list> tail } |cons
```

A payload of schema `list` is a derivation tree of this grammar. For instance, a list containing a single boolean value `true` can be represented by the following derivation:

```
<list>
  -- (rule 4) --> { <bool> head, <list> tail } |cons
                     |            |
                     |            -- (rule 3) --> {} |nil
                     |
                     -- (rule 1) --> {} |true
```

This derivation tree corresponds to the payload generated by the constant relation `{ {} |true head, {} |nil tail } |cons`.

Representing schemas as automata (or CFGs) provides each schema with a well-defined structure, independent of the names used in the source code. This allows for canonical normal forms and for comparing schemas for equality by structure alone.

---

## **3.2 States and Transitions**

Each schema structure introduces one or more *states* in the automaton. A union or a product schema corresponds to a state, and the variants or fields correspond to transitions to other states.

For example, consider the `bool` schema:

```k-lang
bool = ?< {} true, {} false >;
```

This schema translates to an automaton with two states:

- A root state, let's call it `C0`, representing the `bool` schema itself (a union).
- A state `C1` representing the empty product `{}`.

From the root state `C0`, there are two transitions:

- A transition labeled `true` to state `C1`.
- A transition labeled `false` to state `C1`.

`C0` is the root state of the schema, and `C1` is a leaf state, representing an empty unit value.

---

## **3.3 Canonical Form**

Different schema expressions can describe the same automaton. For example:

```k-lang
pair = ?{ < {} false, {} true > x, < {} false, {} true > y };
pair2 = ?{ < {} true, {} false > x, < {} true, {} false > y };
```

The schemas `pair` and `pair2` are structurally equivalent because the choice order in a union does not alter the underlying accepted set of trees. Canonicalization is the process of removing these superficial differences by erasing local names and renumbering states to produce a single stable representation for each unique schema structure.

The canonical form is generated by traversing the schema's graph structure starting from its root state. The process ensures a unique representation by following a consistent ordering:

1. **Start at the Root**: Assign the number `C0` to the root state of the schema.
2. **Explore Neighbors**: Visit all states reachable from `C0`. Sort the transitions alphabetically by their labels (field or variant names) and assign consecutive numbers (`C1`, `C2`, ...) to the destination states in that order.
3. **Iterate**: Move to the next state in the numbered sequence (`C1`, then `C2`, etc.) and repeat the process for any of its neighbors that have not yet been numbered.
4. **Complete**: Continue until all reachable states have been assigned a unique number.

This traversal produces a unique and deterministic numbering for any finite directed graph, ensuring that any two structurally identical schemas will have the exact same canonical representation.

---

## **3.4 Examples**

For a schema representing binary natural numbers:

```k-lang
bnat = ?< Bnat 0, Bnat 1, {} _ > = Bnat;
```

the canonical automaton form is:

```text
C0 = < C0 "0", C0 "1", C1 "_" >;
C1 = {};
```

The automaton has two states. `C0` is a recursive state that recognizes sequences of "0"s and "1"s, while `C1` is the terminal state, marked by the "_" transition.

---

## **3.5 Normalization Process**

When compiling a program, the following steps are taken to normalize schemas:

1. **Collect**: Gather all schema structures and filters from the program.
2. **Expand**: Recursively replace named relation references with their underlying schema structures until only products and unions remain.
3. **Deduplicate**: Eliminate duplicate schema structures by comparing them structurally.
4. **Canonicalize**: Assign stable state numbers to the unique schemas to produce their canonical text representation.

This process is deterministic, ensuring that the same schema structure always produces the exact same canonical form.

---

## **3.6 Hash-Based Naming**

To create a globally unique and stable index for each schema, the compiler computes a digest of its canonical automaton representation. This hash becomes a fixed-width content address for the schema in the registry.

For example:

```text
Canonical Automaton: C0=<C0"0",C0"1",C1"_">;C1={}
      ↓
     Hash
      ↓
Identifier: @VtPHxGf5GNMzzyVFxtv7gegFfJRYapBGtCeyV56bs5Zb
```

Program objects and contracts can refer to schemas by their hash-based identifiers (prefixed with `@`) without ambiguity.

---

## **3.7 Interpretation**

The canonical representation of a schema can be interpreted as:

- A finite set of states, `C0…Cn`.
- Each state is either a product (a record with named fields) or a union (a set of variants).
- Transitions between states are labeled with strings (field or variant names).

Every payload tree of a given schema is a finite tree that is accepted by this automaton.

---

## **3.8 Summary**

- Schemas in `k` denote sets of finite, labeled trees.
- Every schema can be expressed as a finite tree automaton or a context-free grammar.
- The canonical form eliminates naming differences, providing a single representation for structurally identical schemas.
- Hash-based naming gives each unique schema a stable and globally unique content-addressable identifier.
